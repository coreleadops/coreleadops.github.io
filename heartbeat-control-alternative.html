What happened to Heartbeat Control?

Heartbeat Control by WP Media was a popular utility — 80,000+ active installations — for controlling the WordPress Heartbeat API. Then development stopped. Here is the publicly observable record:

No update in over three years. The last release was version 2.0.1 on August 31, 2023. It is listed as tested only up to WordPress 6.3.

WordPress.org itself flags it. The plugin page displays the official warning: "This plugin hasn't been tested with the latest 3 major releases of WordPress. It may no longer be maintained or supported and may have compatibility issues when used with more recent versions of WordPress."

~127 unresolved support threads. Zero threads resolved in the last two months. Threads titled "DEAD PLUGIN" (March 2024), "Plugin Flagged Abandoned" (September 2025), and multiple "Is this plugin abandoned?" threads have no author response.

Users report fatal errors on PHP 8.1 and 8.2. A support thread documents an Uncaught TypeError (class "CMB2_Hookup" not found) on currently supported PHP versions. We have not independently reproduced this failure, so we report it as users describe it — but the thread has sat unanswered since March 2024, and the plugin still bundles CMB2 v2.10.1 from 2021.

The most recent thread (September 23, 2026) is an automated version-compatibility review notice: the plugin "encountered an issue and requires review." It remains unresolved.

If you run Heartbeat Control, nothing about this is your fault — it was a good plugin. But every month it goes without maintenance, the gap between it and current WordPress/PHP grows. That's why we built the replacement.

Evidence last verified: September 28, 2026, from the public WordPress.org plugin page and support forum.

Migration: deactivate the old, activate the new

  1. Install Heartbeat Manager from the WordPress plugin directory (launching soon — get notified).
  2. Activate it. On first run it detects Heartbeat Control's settings and imports them — you'll see a confirmation notice on the settings page. Nothing to reconfigure.
  3. Deactivate Heartbeat Control. Running both is unnecessary; Heartbeat Manager now owns the heartbeat settings.

Technical note: migration reads the legacy heartbeat_control_settings option and writes it to the new heartbeat_manager_settings format. Your old settings are left untouched until you remove the old plugin.

Frequently asked questions

Is Heartbeat Control actually abandoned?

We can't speak for its author. What we can document: no release since August 2023, a WordPress.org "may no longer be maintained" warning, ~127 unresolved support threads, and unanswered breakage reports. Draw your own conclusions — that's why we cite dates and links.

Will my Heartbeat Control settings carry over?

Yes. Heartbeat Manager detects the old plugin's settings on activation and imports them automatically, with a confirmation notice on the settings page.

Will disabling the heartbeat break autosave?

Disabling the heartbeat in the post editor location stops post autosaves and post-locking warnings. If you rely on autosave, use "Modify frequency" (e.g. 120 seconds) for the editor instead of "Disable".

Does it work with page builders and WooCommerce?

Yes. Heartbeat Manager only touches the core heartbeat script handle and the heartbeat_settings filter — it doesn't modify any other plugin's behavior.

Is it really free?

Yes. Everything Heartbeat Control did is free in Heartbeat Manager. A future Pro tier will add new capabilities only — nothing the old plugin did for free will ever be paywalled.
